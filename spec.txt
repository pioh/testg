# Спецификация тестовой утилиты

## Основная структура проекта
- Тестовая утилита в подпакете ./load_test/ на языке Go с использованием fasthttp
- Модуль app-manager для управления тестируемыми приложениями
- тестовая утилита использует app-manager для запуска и остановки приложений

## Требования к тестовой утилите
1. Универсальная, может тестировать любые приложения с помощью app-manager
2. Матричное тестирование параллельности и глубины:
   - Постепенное увеличение сложности: for(parallel=32;;parallel*=2) for(depth=1;;depth*=2)
   - Каждый тест должен выполняться duration секунд (задается параметром --duration), затем приложение перезапускается
   - Остановка усложнения, если обработка первой пачки параллельности занимает больше duration или процент ошибок больше 50%
   - Для каждого parallel находим максимально сложный depth, дальше переходим к следующему parallel
   - Если при depth=1 не справляется с текущим parallel, то выходим из обоих циклов
   - Максимальная параллельность около 128 тысяч
3. Сбор и отображение статистики:
   - Время выполнения первого запроса
   - Время обработки первой пачки размером parallel (время от начала теста до момента, когда количество успешно обработанных запросов достигло значения parallel)
   - Общее время выполнения для текущей параллельности
   - Изменение латентности по секундам
   - Использование CPU и памяти (сбор каждые 200мс по pid из app-manager)
   - Время запуска приложения (с момента запуска до готовности принимать запросы)
   - обычные статистики которые принято собирать в таких тестах, включая перцентили
   - в каждой строке должна быть статистика для каждого приложения/конфига
4. Перезапуск тестируемого приложения через app-manager для каждой итерации depth/parallel
5. Оптимизированная реализация на Go с использованием fasthttp

## Требования к app-manager
1. Запуск приложений и возврат их PID
   - Ждет пока приложение запустится и ответит на 100 запросов
   - Возвращает PID и время запуска в JSON-формате
   - НЕ собирает метрики по приложениям - это задача load_test
   - Автоматически останавливает все запущенные приложения перед запуском нового
2. Отображение всех запущенных приложений
   - При запуске сохраняет pid и название приложения в файл в корне проекта
   - При проверке запущенных приложений сверяет pid и т.д. чтобы понять какие еще работают
   - Обновляет файлик удаляя оттуда те что уже не запущены
3. Остановка приложений по PID или имени
4. Хранение списка тестируемых приложений и их конфигураций
   - Конфигурация приложений хранится в отдельном файле для удобного редактирования
5. Может запустить любое приложение просто по имени конфига
6. Может вернуть список доступных для запуска приложений
   - Каждая конфигурация это отдельный app со своим именем

## Взаимодействие load_test и app-manager
1. load_test запрашивает у app-manager запуск приложения
2. app-manager запускает приложение, проверяет его работоспособность через 100 запросов и возвращает PID
3. load_test получает PID и собирает метрики по этому PID (CPU, память и т.д.)
4. После завершения тестирования load_test запрашивает у app-manager остановку приложения
5. Для следующей итерации тестирования процесс повторяется (новый запуск приложения)

## Требования к тестируемым приложениям
1. Обработка параметров в URL: left=X&rnd={random()}
2. При получении запроса:
   - Уменьшение параметра left на 1
   - Новый запрос к тому же эндпоинту с уменьшенным left
   - При left=0 прекращение запросов и возврат параметра rnd
3. Логирование только в случае ошибок:
   - Минимизация логов для повышения производительности
   - Все тестируемые приложения должны писать логи только при возникновении ошибок

## Типы тестируемых приложений
1. Java:
   - java-virtualThreads: Java с виртуальными потоками
   - java-fixedThreads24: Java с фиксированным пулом из 24 потоков
   - java-fixedThreads1024: Java с фиксированным пулом из 1024 потоков
   - java-fixedThreads24AsyncNIO: Java с фиксированным пулом из 24 потоков и асинхронным NIO
2. GraalVM Native:
   - graalvm-native-virtualThreads: Нативная сборка с виртуальными потоками
   - graalvm-native-fixedThreads24: Нативная сборка с фиксированным пулом из 24 потоков
   - graalvm-native-fixedThreads1024: Нативная сборка с фиксированным пулом из 1024 потоков
   - graalvm-native-fixedThreads24AsyncNIO: Нативная сборка с фиксированным пулом из 24 потоков и асинхронным NIO
3. Go:
   - go-fasthttp: Go-приложение использующее fasthttp
   - go-stdlib: Go-приложение использующее стандартный net/http
   - go-fasthttp-maxprocs1: Go-приложение с fasthttp и GOMAXPROCS=1
   - go-stdlib-maxprocs1: Go-приложение со стандартным net/http и GOMAXPROCS=1

## Оптимизации сборки Go-приложений
1. Отключение CGO (CGO_ENABLED=0) для избежания зависимостей от системных библиотек C
2. Удаление отладочной информации и символов (-ldflags="-s -w") для ускорения загрузки
3. Удаление путей к исходному коду (-trimpath) для чистоты сборки
4. Расширенные оптимизации компилятора (-gcflags="-m=2") для повышения производительности
5. Использование чистых Go-реализаций для сетевого стека и пользовательских функций (-tags=netgo,osusergo)
